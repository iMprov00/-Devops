## 1. Запуск

Первая строка файла — shebang (шимбэнг, указатель программы): `#!/usr/bin/env bash`. Программа `env` ищет `bash` в PATH (списке каталогов с командами) и запускает файл ею.

- `bash script.sh` — ты сам вызываешь bash; право на выполнение файла не обязательно.
- `./script.sh` — «в текущем каталоге»; система читает shebang. Нужно право выполнять: `chmod u+x script.sh` (`u+x` — только владельцу, для своего учебного файла).

Строки с `#` — комментарии, кроме этой первой строки shebang. Команды в терминале и в файле означают одно и то же.

## 2. Переменные, подстановка и аргументы

Пробелов вокруг `=` нет: `name="Максим"`. Двойные кавычки подставляют значение, одинарные оставляют текст как есть.

`$(...)` подставляет стандартный вывод (stdout) команды и отрезает завершающие переводы строк: `today=$(date '+%Z %z')`.

- `$1` — первый аргумент, `$#` — число аргументов.
- Пути с пробелами бери в кавычки и при запуске, и в скрипте.
- Сначала проверь `$#`, потом бери `$1`. Если включён режим «неопределённая переменная — ошибка» (`nounset` / `set -u`), обращение к отсутствующему `$1` само станет ошибкой.

Раскрытие имён (glob):

```bash
grep -F WARNING "$dir"/*.log    # кавычки защищают путь папки; *.log раскрывает оболочка
grep -F WARNING "$dir/*.log"    # весь шаблон в кавычках: это не glob, ищут файл с таким именем
```

## 3. Условия: `[[ ]]` и код команды

`if` смотрит **код завершения**, не текст на экране. Код 0 — успех (условие истинно), любой другой — неуспех.

```bash
if [[ $# -eq 0 ]]; then ...        # -eq — равно (для чисел)
if [[ ! -d "$folder" ]]; then ...  # -d — это существующий каталог
# -n — строка не пустая; -z — строка пустая
if grep -q -F WARNING sample.txt; then ...  # смотрит код grep
```

`[[ ]]` — проверка условий в bash. `[ ]` и команда `test` — другой, более старый синтаксис. Их не смешивают в одном условии: правила кавычек и операторов различаются.

## 4. Коды, потоки и `2>/dev/null`

`exit 0` — штатный успех, ненулевой `exit` — ошибка. Код предыдущей команды хранится в `$?`. Смотри его сразу или сохрани в переменную: даже следующий `echo` его перезапишет.

- stdout — обычный результат; stderr — поток ошибок.
- `>&2` направляет сообщение в stderr, чтобы оно не смешалось с результатом.
- `2>/dev/null` отбрасывает stderr в «никуда» (null). Он **скрывает** сообщение, но **не исправляет** ошибку и не меняет сам факт сбоя.

Конвейер `|` передаёт только stdout. Без специального режима (`pipefail`) код всего конвейера — код **последней** команды. После `grep ... | wc -l` в `$?` обычно код `wc` (часто 0), даже если grep вернул 1 или 2.

## 5. grep: коды и ложный ноль

Коды grep: **0** — совпадения найдены; **1** — файлы прочитаны, совпадений нет; **2** — ошибка (нет файла, нет прав и т.п.). Код 1 — обычный ответ «не нашли», не авария программы.

`grep -c` по нескольким файлам печатает отдельный счётчик на каждый файл. `| wc -l` после этого посчитает **строки-счётчики**, а не сумму совпадений.

Типовой антипример (учебный путь, ищем WARNING, не готовый отчёт):

```bash
grep -h WARNING ~/study-demo/logs/*.log 2>/dev/null | wc -l
```

Здесь ошибки чтения выброшены, а код конвейера — у `wc`. Можно получить `0` и при нечитаемом файле, и если шаблон `*.log` ни на что не раскрылся (оболочка может оставить его буквально). Это не то же самое, что «ноль совпадений».

Различай: (1) файлы прочитаны, нужных строк нет — ноль совпадений; (2) файлов `.log` нет; (3) файл не удалось прочитать. Ошибку чтения и отсутствие файлов нельзя подменять нулём.

## 6. Как проверять скрипт, в том числе от ИИ

`bash -n script.sh` проверяет только синтаксис: файл не выполняется. Это не проверка безопасности и не доказательство правильной логики.

Перед запуском прочитай **все** команды: нет ли изменения или удаления файлов, сети, отправки данных. Запускай без `sudo`, только в домашней песочнице и на выдуманных данных.

Минимальный список проверок (делает сам пользователь, только домашняя ВМ):

1. обычный запуск с учебной папкой;
2. без аргумента;
3. несуществующая папка;
4. путь с пробелом;
5. файлы есть, совпадений нет;
6. в папке нет `.log`;
7. файл не читается;
8. служба остановлена вручную — скрипт не должен её запускать сам; вернуть службу обратно тоже вручную и только сам пользователь.

Автозапуск службы из учебного скрипта не нужен. Остановку и запуск за пользователя эта шпаргалка не выполняет.
