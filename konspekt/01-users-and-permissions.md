# 01. Пользователи, группы и права доступа

> Шпаргалка по шагу №1 «Новенькие в отделе» (сдан 16.11.2026).
> Все примеры на выдуманных пользователях `ivan`, `masha`, группе `buh` и папке `/srv/demo`.
> ⚠️ Команды, которые меняют права и пользователей, пробуй только на домашней виртуалке.

## 1. Пользователи и группы

| Файл | Что хранит | Кто может читать |
|---|---|---|
| `/etc/passwd` | пользователи: `имя:x:UID:GID:комментарий:домашняя_папка:shell` | все |
| `/etc/shadow` | хеши паролей (не сами пароли) | только root |
| `/etc/group` | группы: `имя:x:GID:участник1,участник2` | все |

- **Первичная группа (primary)** у пользователя одна, записана в `/etc/passwd`. Новые файлы по умолчанию получают её.
- **Дополнительные группы (supplementary)** перечислены в `/etc/group`. Через них выдают общий доступ.

```bash
sudo useradd -m -s /bin/bash ivan   # -m создать домашнюю папку, -s задать shell; пароль НЕ задаёт
sudo adduser masha                  # обёртка Ubuntu/Debian: папка, группа, пароль — интерактивно
sudo passwd ivan                    # задать/сменить пароль (ввод не отображается — это нормально)
sudo groupadd buh                   # создать группу
sudo usermod -aG buh ivan           # ДОБАВИТЬ в дополнительную группу
sudo gpasswd -d ivan buh            # убрать из группы
id ivan                             # UID, GID и все группы
groups ivan                         # только группы
getent group buh                    # кто в группе
```

### ⚠️ Слабое место: `usermod -G` без `-a`

| Команда | Что происходит |
|---|---|
| `usermod -aG buh ivan` | `buh` **добавляется** к имеющимся группам ✅ |
| `usermod -G buh ivan` | все дополнительные группы **заменяются** на `buh` ❌ |

Если пользователь был в `sudo`, после `usermod -G buh` он **потеряет sudo**. Если это был ты сам, потеряешь права администратора.
Запомни: **-a = append = «добавить»**. Без `-a` не пиши.

### ⚠️ Слабое место: новая группа работает только после перелогина

Список групп выдаётся процессу **в момент входа** и потом не перечитывается.

```
usermod -aG buh ivan
  /etc/group уже изменён  →  `id ivan` (читает файлы) группу ПОКАЖЕТ
  открытая сессия ivan    →  просто `id` группу НЕ покажет, доступа нет
```

Как применить:
- выйти и зайти заново (новое SSH-подключение);
- `su - ivan` — полноценный вход с новым списком групп;
- `newgrp buh` — запустить новый shell с этой группой в текущей сессии.

## 2. Права rwx

```
drwxrws---  2 root buh 4096 ... /srv/demo
│└┬┘└┬┘└┬┘     │    │
│ │  │  │      │    └ группа
│ │  │  │      └ владелец
│ │  │  └ other (остальные)
│ │  └ group  (группа)
│ └ user   (владелец)
└ тип: d папка, - файл, l ссылка
```

### ⚠️ Слабое место: разбор по тройкам

Всегда делим строку прав на **три тройки по три символа**: `rwx | rws | ---`.
Система проверяет **один** подходящий круг сверху вниз и дальше не смотрит:

1. ты владелец → действуют только права владельца;
2. иначе ты в группе файла → только права группы;
3. иначе → права other.

root проверку прав почти всегда обходит, поэтому проверяй доступ от обычного пользователя.

### Числовая запись

`r = 4`, `w = 2`, `x = 1`, складываем в каждой тройке:

| Буквы | Число | | Буквы | Число |
|---|---|---|---|---|
| `rwx` | 7 | | `r--` | 4 |
| `rw-` | 6 | | `--x` | 1 |
| `r-x` | 5 | | `---` | 0 |

Примеры: `rwxr-x--- = 750`, `rw-r--r-- = 644`, `rwxrwx--- = 770`.

### Права для файла и для папки — разные вещи

| Право | Для файла | Для папки |
|---|---|---|
| `r` | читать содержимое | видеть **список имён** (`ls`) |
| `w` | менять содержимое | **создавать / удалять / переименовывать** файлы внутри |
| `x` | запускать | **входить** (`cd`) и обращаться к файлам внутри |

Правила:
- без `x` на папке не работают ни `r`, ни `w`;
- `x` нужен на **каждой** папке пути (`/`, `/srv`, `/srv/demo`), иначе `Permission denied` даже при 777 на файле;
- удалить файл может тот, у кого есть `w` на **папку** (если нет sticky bit);
- «остальные не могут даже заглянуть» означает, что у other на папке нет ни `r`, ни `x` (`---`).

```bash
ls -l                 # права файлов в папке
ls -ld /srv/demo      # права самой папки (-d = не заходить внутрь)
namei -l /srv/demo/f  # права каждой папки по пути
```

### Смена владельца и прав

```bash
sudo chown ivan:buh /srv/demo   # владелец и группа сразу
sudo chgrp buh /srv/demo        # только группа
chmod 750 /srv/demo             # числом
chmod g+w,o-rwx /srv/demo       # символьно: u/g/o/a, +/-/=, r/w/x
chmod -R u=rwX,g=rX,o= dir      # рекурсивно; большая X ставит x только папкам
```

⚠️ `chmod -R` / `chown -R` на системных папках (`/`, `/etc`, `/usr`) ломают систему. `chmod -R 777` «чтобы заработало» — так не делают.

## 3. Специальные биты

Четвёртая цифра спереди: `chmod 2770` = `770` + setgid.

| Бит | Число | Где | Что делает | В `ls` |
|---|---|---|---|---|
| setgid | 2 | на папке | новые файлы получают **группу папки** | `s` у группы |
| suid | 4 | на программе | запуск с правами **владельца файла** (`/usr/bin/passwd`) | `s` у владельца |
| sticky | 1 | на общей папке | удалить файл может только его владелец (`/tmp`) | `t` у other |

### ⚠️ Слабое место: `s` вместо `x`

В позиции `x` одна буква показывает два бита:

| У группы | Значит |
|---|---|
| `x` | только x |
| `s` | x **+** setgid ✅ |
| `S` | setgid **без** x ⚠️ группа не может войти в папку |
| `-` | ничего |

То же самое у other: `t` значит x + sticky, `T` значит sticky без x.

```bash
chmod g+s /srv/demo   # поставить setgid
chmod g-s /srv/demo   # убрать
```

Чтобы setgid работал, нужны все звенья: группа есть → люди в группе → папка принадлежит группе → бит стоит.
Бит действует только на **новые** файлы.
Разницу видно только у пользователя, у которого **первичная** группа другая. Если у тестового пользователя первичная группа уже `buh`, файлы получат `buh` и без setgid.

## 4. umask

### ⚠️ Слабое место: стартовые права и расчёт

1. Программа создаёт файл с базой: **666** (`rw-rw-rw-`) для файла, **777** (`rwxrwxrwx`) для папки. У файлов `x` в базе нет никогда.
2. umask **убирает** указанные биты.

| umask | Файл | Папка |
|---|---|---|
| `022` | 666 − 022 = **644** `rw-r--r--` | 777 − 022 = **755** `rwxr-xr-x` |
| `002` | 666 − 002 = **664** `rw-rw-r--` | 777 − 002 = **775** `rwxrwxr-x` |
| `027` | **640** `rw-r-----` | **750** `rwxr-x---` |
| `077` | **600** `rw-------` | **700** `rwx------` |

Строго это не вычитание, а побитовое «база И НЕ маска»: например, umask `033` даст файлу `644`, а не `633`. Для обычных значений можно считать вычитанием.

```bash
umask          # текущее значение, например 0002
umask -S       # что ОСТАЁТСЯ, буквами: u=rwx,g=rwx,o=rx
umask 027      # поменять только для текущей сессии
grep -E "^UMASK|^USERGROUPS" /etc/login.defs
```

Где задаётся (обычно в Ubuntu): `/etc/login.defs` (`UMASK`, `USERGROUPS_ENAB`), PAM-модуль `pam_umask`, `~/.profile` / `~/.bashrc`; у сервисов systemd — `UMask=` в unit-файле.

**setgid отвечает за то, какая группа будет у файла, а umask — за то, какие права получит эта группа.** Для общей папки нужны оба.

## 5. sudo

- `sudo команда` выполняет команду от root, а пароль спрашивается **твой**. Все вызовы пишутся в лог (`/var/log/auth.log`).
- В `/etc/sudoers` в Ubuntu уже есть `%sudo ALL=(ALL:ALL) ALL`: `%` означает группу, правило разрешает группе `sudo` всё.
- В Ubuntu дать sudo = добавить в группу `sudo`. В CentOS/RHEL группа называется `wheel`.

```bash
sudo usermod -aG sudo ivan     # выдать sudo (и не забыть про перелогин!)
sudo gpasswd -d ivan sudo      # забрать
sudo -l -U ivan                # что ivan можно через sudo
sudo whoami                    # под пользователем: должно вывести root
```

### visudo

`/etc/sudoers` правят **только** через `visudo`:
- проверяет синтаксис перед сохранением (ошибка в sudoers ломает sudo у всех);
- блокирует файл от одновременной правки;
- правит копию и записывает её, только если проверка прошла.

```bash
sudo visudo                            # основной файл
sudo visudo -f /etc/sudoers.d/ivan     # своё правило в отдельном файле
sudo visudo -c                         # только проверить все файлы
```

Пример узкого правила в `/etc/sudoers.d/ivan`:
```
ivan ALL=(ALL) /usr/bin/systemctl restart nginx
```

## 6. Как проверять результат

```bash
id ivan                # группы
ls -ld /srv/demo       # владелец, группа, права, биты папки
su - ivan              # войти пользователем (дефис = полный вход, свежие группы)
touch /srv/demo/test   # можно ли писать
ls -l /srv/demo        # группа и права нового файла
sudo whoami            # есть ли sudo
```

## 7. Частые ошибки

- `usermod -G` без `-a` → пропали группы, в том числе `sudo`.
- Забыл перелогиниться после добавления в группу.
- `sudo mkdir` создал папку `root:root` → забыл сменить группу.
- `S` вместо `s` → setgid есть, а `x` у группы нет.
- Нет `x` на одной из папок пути → `Permission denied`.
- Правка sudoers через nano → сломанный sudo.
- `chmod -R 777` вместо нормальной настройки группы.
