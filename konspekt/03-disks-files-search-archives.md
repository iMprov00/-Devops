## Повторить

Эти пункты по отчёту не подтверждены. К этим пунктам вернёмся в дальнейшей практике.

1. **Три непустых файла разного размера.** Факт создания и сравнение размеров не приняты. Не подменяй это разреженным `truncate`: для задания нужны обычные файлы с реальным содержимым разной длины.
2. **Три самых больших файла.** Общий приём — в разделе про `sort`. Готовую цепочку задания сюда не вписываю. Сначала реши, что сравниваешь: видимую длину или выделенные блоки.
3. **Общий подсчёт строк ERROR.** Ошибка: `grep -c … файл1 файл2 файл3 | wc -l` считает **строки-счётчики** (по одному числу на файл). Для трёх файлов получится `3`, даже если совпавших строк было пять. Как считать правильно — в разделе про `grep`.
4. **Исчерпание inode.** Вопрос «что будет, если кончатся inode» отдельно не закрыт. Краткий ответ: `df -i` покажет `IFree` 0 и `IUse%` 100%, а `df -h` при этом ещё может показывать свободные гигабайты. Новый файл или каталог не создастся, сообщение будет `No space left on device` («на устройстве не осталось места»). Оно же бывает при нехватке **блоков**, поэтому смотрят и `df -h`, и `df -i`.

## 1. df: блоки и inode — два разных лимита

**Файловая система (ФС)** хранит имя в каталоге, **inode** (айнод, карточка: тип, права, даты, ссылки на данные) и **блоки** (сами данные). Каталог тоже занимает inode. Один inode может указывать на много блоков, поэтому проценты по месту и по inode независимы и не обязаны совпадать.

```bash
df -h /     # человекочитаемые размеры (K, M, G) по блокам
df -i /     # учёт inode
```

Колонки `df -h`: `Filesystem` — раздел, `Size` — размер ФС, `Used` — занято, `Avail` — доступно обычному пользователю, `Use%` — доля использования, `Mounted on` — куда примонтирована (точка монтирования). Колонки `df -i`: `Inodes` — всего карточек, `IUsed` — занято, `IFree` — свободно, `IUse%` — доля занятых inode.

Пример арифметики (не точные блоки с твоей машины): если занято 271243 inode из 1638400, это ≈ 16,56%, а `IUse%` покажет `17%` — дробный процент округляют вверх.

По выводу `df -h` нельзя считать точные блоки или «средний размер файла». `-h` округляет, а резерв для root уменьшает `Avail`, поэтому `Used + Avail` может не сойтись с `Size`. У GNU df колонка `Use%` обычно равна `Used / (Used + Avail)` по точным значениям: на знаменатель влияет резерв, не только округление, и процент может не совпасть с `Used / Size` из колонок `-h`.

После удаления последней жёсткой ссылки и закрытия открытых дескрипторов освобождаются inode и выделенное пространство, не обязательно равное видимой (логической) длине файла.

## 2. ls, du и ссылки

`ls -l` показывает **видимую длину** файла в байтах (сколько содержимого он объявляет). `ls -lh` то же «по-человечески». `du` показывает **выделенные блоки** (disk usage — использование диска).

```bash
ls -l  ~/study-demo/sizes-demo/tiny.txt   # для printf 'hi\n' длина 3 байта
ls -lh ~/study-demo/demo-tree             # содержимое каталога
ls -ldh ~/study-demo/demo-tree            # сам каталог, не сумма файлов
du -h ~/study-demo/demo-tree
du -sh ~/study-demo/demo-tree             # -s — только итог (summary)
du -h --max-depth=1 ~/study-demo/demo-tree
du -h --apparent-size ~/study-demo/sizes-demo/hole.dat
```

Без `-d` команда `ls` по каталогу печатает **содержимое**. С `-ld` — **сам каталог** (длина его записи, часто около 4K, не сумма файлов). Даже крошечный файл обычно занимает минимум один блок, часто 4K: сто мелких файлов едят больше, чем кажется по `ls -l`.

**Разреженный файл** (sparse) объявляет большую длину, а блоков почти не занимает. Учебный пример, это не способ набрать файлы задания:

```bash
truncate -s 20K ~/study-demo/sizes-demo/hole.dat
ls -l ~/study-demo/sizes-demo/hole.dat   # длина 20480 байт (20K)
du -h ~/study-demo/sizes-demo/hole.dat   # блоки: часто 0 или 4K, смотри свой вывод
```

`du` не врёт: по умолчанию он считает выделенные блоки, не объявленную длину. Выделенные блоки — учёт ФС; на некоторых ФС с копированием при записи они не всегда равны уникальным физическим ячейкам.

**Жёсткая ссылка** (`ln`) — второе имя того же inode, те же данные. `ls -li` покажет один номер inode у обоих имён. Удаление одного имени не удаляет данные, пока осталась другая жёсткая ссылка. Если процесс ещё держит файл открытым, место по `df` может не освободиться, пока дескриптор не закроют.

**Символическая ссылка** (`ln -s`) — отдельный inode, внутри хранится путь. Если цель удалили, ссылка остаётся **битой** (dangling): при чтении будет `No such file or directory` («нет такого файла или каталога»).

```bash
ln    ~/study-demo/keep.txt ~/study-demo/keep-hl.txt   # жёсткая: тот же inode
ln -s keep.txt ~/study-demo/keep-s.txt                 # символическая: свой inode и путь
ls -li ~/study-demo/keep.txt ~/study-demo/keep-hl.txt ~/study-demo/keep-s.txt
```

## 3. Потоки, перенаправление и код выхода

У команды три потока: **stdin** — стандартный ввод, **stdout** — стандартный вывод (обычный результат), **stderr** — стандартный поток ошибок.

| Запись | Смысл |
|---|---|
| `>` | stdout в файл, **перезаписывает** (обрезает) существующий |
| `>>` | stdout дописать в конец |
| `2>` | stderr в файл |
| `\|` | конвейер: stdout слева становится stdin справа; stderr в трубу сам не уходит |

```bash
printf 'первая\n' > ~/study-demo/hello.txt      # создать или затереть
printf 'вторая\n' >> ~/study-demo/hello.txt     # дописать
ls ~/study-demo/no-such-file | wc -l
```

Команда `ls`: на экране будет `ls: cannot access '…': No such file or directory` («невозможно обратиться: нет такого файла или каталога») — это stderr. До `wc -l` оно не дойдёт, поэтому справа напечатается `0`.

Код выхода смотри **отдельной командой**, не через конвейер. В трубе `$?` относится не к тому, что ты думаешь.

```bash
diff -q ~/study-demo/alpha.txt ~/study-demo/alpha2.txt
echo $?
```

`0` — одинаковые (вывода нет), `1` — есть различия, `2` — ошибка, например нет файла (`No such file or directory`).

## 4. sort и отбор самых больших

`sort` читает строки и печатает их в другом порядке, сам файл не меняет. Без флагов сравнение **текстовое** (лексикографическое, по символам слева направо).

```bash
printf '%s\n' 9 10 2 > ~/study-demo/nums.txt
sort ~/study-demo/nums.txt      # 10  /  2  /  9    — символ '1' раньше '2'
sort -n ~/study-demo/nums.txt   # 2   /  9  /  10   -n — как числа
sort -nr ~/study-demo/nums.txt  # 10  /  9  /  2    -r — наоборот
```

`-h` понимает суффиксы `K`, `M`. Учебный текст, не настоящие файлы на 2M:

```bash
printf '%s\n' '900K' '2M' '30K' '1M' > ~/study-demo/human-sizes.txt
sort -h ~/study-demo/human-sizes.txt    # 30K  /  900K  /  1M  /  2M
sort -hr ~/study-demo/human-sizes.txt   # 2M   /  1M    /  900K /  30K
```

Если величина не в первом столбце: `-k2,2n` — только второе поле, как число (`apple 10`, `banana 2`, `carrot 9` → сначала `banana 2`). `head -n 3` берёт первые три строки уже готового потока, сам не сортирует. После `sort -h` в начале меньшие; для «самых больших» сначала `-hr` или `-nr`.

Общий приём «самые большие файлы» (не готовая цепочка задания): 1) выбрать метрику — видимая длина или выделенные блоки; 2) получить строки «размер путь»; 3) отсортировать числом или `-h`, для крупных сначала `-r`; 4) взять нужное число строк через `head`. Не смешивай длину из `find`/`ls` с блоками из `du`.

## 5. find

Сначала путь (узкая область), потом условия. Кавычки у шаблона обязательны: иначе оболочка сама подставит список из текущей папки.

`-type f` — только обычные файлы. Суффикс `c` у `-size` — байты. У GNU find `-size` смотрит на **видимую длину** (как `ls -l`) и округляет вверх до указанной единицы; это не блоки из `du`. Для точного порога в байтах используй `c`. `-printf` — формат самого `find`, не команда `printf`. `%s` — длина в байтах, `%p` — путь, `\n` — перевод строки. Порядок строк `find` не гарантирует.

```bash
find ~/study-demo/sizes-demo -type f
find ~/study-demo/sizes-demo -type f -name '*.txt'
find ~/study-demo/sizes-demo -type f -size 11c     # ровно 11 байт
find ~/study-demo/sizes-demo -type f -size +10c    # строго больше 10 байт
find ~/study-demo/sizes-demo -type f -printf '%s %p\n'
```

## 6. grep: имена, номера, регистр и общий итог

`-F` — искать обычную подстроку, не регулярное выражение. `-H` — имя файла, `-n` — номер строки, `-i` — игнорировать регистр, `-r` — обходить подпапки (корень держи узким), `-h` — не печатать имена, `-c` — число совпавших **строк по каждому файлу**.

`--color=never` отключает раскраску: в PowerShell подсветка часто синяя, а цветовые коды мешают копировать вывод и портят конвейер.

```bash
printf '%s\n' 'ERROR failed' 'Error retry' 'error skip' > ~/study-demo/case.txt
grep -F ERROR ~/study-demo/case.txt     # только строка ERROR failed
grep -Fi ERROR ~/study-demo/case.txt    # все три: ERROR, Error и error
```

`grep` находит **строки с фрагментом**, а не число повторов внутри одной строки. Подстрока `ERROR` найдётся и внутри `ERRORS`.

Ловушка общего итога (выдуманные логи, пять строк `WARNING` в трёх файлах):

```bash
# app.txt: две строки WARNING; sys.txt: две; misc.txt: одна
grep -c -F WARNING ~/study-demo/app.txt ~/study-demo/sys.txt ~/study-demo/misc.txt
```

Ожидаемый вывод — **три счётчика**, не сумма 5:

```text
/home/improv/study-demo/app.txt:2
/home/improv/study-demo/sys.txt:2
/home/improv/study-demo/misc.txt:1
```

Если это передать в `wc -l`, получится `3` (число строк-счётчиков = число файлов), а не `5`. Правильный общий подсчёт совпавших строк:

```bash
grep -h -F WARNING ~/study-demo/app.txt ~/study-demo/sys.txt ~/study-demo/misc.txt | wc -l
# 5
```

`wc -l` считает символы перевода строки. У обычного вывода `grep` каждая строка заканчивается на `\n`. Если перевод строки в конце отсутствует, GNU `wc -l` покажет меньше видимых строк: `printf 'one\ntwo\n' | wc -l` даёт `2`, а `printf 'one\ntwo' | wc -l` даёт `1`.

Код выхода `grep`: `0` — совпадения есть, `1` — нет, `2` — ошибка. Смотри через `echo $?` следующей отдельной строкой.

## 7. diff: два объекта, не «звёздочка»

`diff` сравнивает **два** объекта. Оболочка раскрывает шаблон `*` в список аргументов, и тогда аргументов может стать не два.

```bash
# так нельзя рассчитывать: dir-a/* развернётся в много файлов
# diff -q ~/study-demo/dir-a/* ~/study-demo/dir-b/*

diff -q  ~/study-demo/alpha.txt ~/study-demo/alpha2.txt   # кратко: отличаются или нет
diff -u  ~/study-demo/alpha.txt ~/study-demo/alpha2.txt   # объединённый формат
diff -rq ~/study-demo/dir-a ~/study-demo/dir-b            # деревья, только факт
diff -ur ~/study-demo/dir-a ~/study-demo/dir-b            # деревья, с текстом
```

`-q` — кратко (`Files … differ`, «файлы различаются»). `-u` — формат с заголовками `---` / `+++`: минус — только в первом файле, плюс — только во втором, пробел — общая строка. `-r` — рекурсивно по каталогам. Если файлы одинаковые, вывода нет и код `0`; код `1` — есть различия; код `2` — ошибка. `diff` сравнивает **содержимое**, а не все метаданные (даты и права могут отличаться при том же тексте).

## 8. tar: архив и сжатие — не одно и то же

`tar` упаковывает файлы в один архив. Сжатие (обычно gzip) — отдельный шаг, его часто включают флагом `-z`.

`-f` берёт **следующее слово как имя архива**. Пиши архив одним путём, не разрывай каталог и имя:

```bash
# верно: один файл-архив, исходник — относительное имя notes после -C
tar -czf ~/study-demo/notes.tar.gz -C ~/study-demo notes

# неверно: -f заберёт только backup/, а logs.tar.gz сочтёт исходником
# tar -czf ~/study-demo/backup/ logs.tar.gz notes
```

`-C` сначала переходит в каталог, поэтому в архив попадают относительные имена вроде `notes/hello.txt`, а не `/home/…`. Архив держи **рядом** с исходной папкой, не внутри упаковываемого дерева.

```bash
tar -tzf ~/study-demo/notes.tar.gz
# notes/
# notes/hello.txt     — это имена, не текст файлов
```

`-c` создать, `-x` извлечь, `-t` оглавление, `-z` gzip, `-v` печатать имена по ходу, `-f` файл архива. Распаковку делай в отдельное пустое дерево, затем сверяй содержимое через `diff`, а не «на глаз» по метаданным:

```bash
mkdir -p ~/study-demo/empty-extract
tar -xzf ~/study-demo/notes.tar.gz -C ~/study-demo/empty-extract
diff -rq ~/study-demo/notes ~/study-demo/empty-extract/notes
```

## 9. Удаление: сначала тот же просмотр, потом -delete в конце

Только в `~/study-demo`, не в папке задания и не от `/`. Команду `rm -rf` не используй. `-delete` необратим: условия `find` читаются слева направо, поэтому `-delete` ставят **после** всех отборов. Если написать его раньше `-name`, можно снести лишнее.

```bash
printf 'temp\n' > ~/study-demo/one.tmp
printf 'keep me\n' > ~/study-demo/keep.txt
find ~/study-demo -type f -name '*.tmp'     # сначала тот же просмотр
# /home/improv/study-demo/one.tmp           # keep.txt в список не входит
```

Когда список проверен и совпадает с задуманным, повтори **те же** путь, `-type f` и `-name`, и только в конце добавь `-delete`. После этого повторный `find … -name '*.tmp'` не должен показывать `one.tmp`, а контролька сохраняется:

```bash
cat ~/study-demo/keep.txt    # keep me
```
